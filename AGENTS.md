# Research working rules

- This repository is the user-authorized destination for future commits and pushes of drone RF separation work. Commit only reviewed research code, plans, and verified reports. Do not add raw datasets, checkpoints, credentials, or unrelated work from the previous repository.
- Exclude remote-controller classes and explicit combined aircraft/controller labels from the aircraft cohort. Keep ambiguous transmitter provenance visible; a product folder name is not proof of airframe-only emission.
- Signal function is not an admission filter: aircraft-origin telemetry, status/control responses, identification broadcasts, and video are all in scope. Absence of video bandwidth is not grounds for exclusion. Review transmitter provenance for all categories, including the initial six; preserve frozen trials while preparing new cohorts.
- Primary mixtures must use I/Q from one dataset and one original RF band. Do not pool datasets for training or mix RFUAV with DroneDetect after the 2026-10-07 user correction. Prepare independent experiments at each dataset's native sample rate. Check receiver/settings within a dataset; dataset membership alone does not prove identical hardware. Preserve earlier frozen cross-band trials as explicitly labeled exploratory results.
- Primary objective: complex I/Q reconstruction, generalization to new source recordings/types, then variable 1–3 source separation and count estimation (user narrowed the immediate scope on 2026-10-06). Four-slot code is retained for compatibility, not scheduled. Performance takes priority over real-time speed. Preserve full model capacity. Use seed 0 for the initial matched comparison.
- Split original recording groups before making windows or synthetic mixtures. Do not claim new windows are independent recordings. Keep held-out data out of model/threshold selection, and keep any previously reserved confirmation files unopened under their existing protocol.
- Existing detector training and DR-NMF D2 remain on user-requested hold. Legacy N power/magnitude trials run in the previous workspace; do not move their files or change frozen source while running. A user message can steer the research but does not itself cancel unrelated authorized trials.
- Report planned, prepared, queued, running, and evaluated states separately. Check the actual process and saved progress before claiming training is active. Never claim perfect separation, general-purpose operation, or publication readiness without evidence.
- The user explicitly requests in-chat reporting after every completed epoch. While actively monitoring, report saved validation metrics (two/three-source NMSE, complex SI-SDR, weakest NMSE), change from the preceding epoch, selected checkpoint, and next running epoch. A link to an automatically updated file alone does not satisfy that request. Keep the turn active through the next promised epoch report when feasible; do not imply that a detached training process can itself send future chat messages.
- Every published result must identify the dataset/split, comparison budget, waveform metrics, and limitations. Keep failed conditions alongside successful ones. A NMF-free U-Net result is not a Deep NMF improvement.
- Read `docs/PLAN_KO.md` and `docs/DATA_POLICY_KO.md` before extending this experiment.
- Run CPU data preparation/analysis alongside GPU training with bounded memory, CPU affinity, and low CPU/I/O priority. Preserve a source snapshot for long-running workers.
- Latest user instruction on 2026-10-10: run the five shortlisted candidates sequentially to 50 logged blocks each: SepTDA-inspired RF, frozen-backbone TF adapter, ordered-context gate, balanced source-interaction head, waveform update guard. This explicitly supersedes the earlier Sep-only/no-other-candidates queue restriction. Resume completed blocks and optimizer/RNG; the balanced head starts fresh from the common parent because its TRAIN4 probe weights were discarded. Maintain one reusable common U-Net control and defer its additional training; do not retrain a control for each candidate. Disclose schedule phases, total updates, and missing matched-budget controls. Preserve frozen earlier protocols; register this order as an execution amendment.
- The user authorized ongoing cleanup: remove obsolete, regenerable artifacts after checking current dependencies; retain a concise result summary and a deletion ledger. Keep active caches/resume state and numerical evidence needed for reported comparisons. Do not indiscriminately remove whole experiment directories.
