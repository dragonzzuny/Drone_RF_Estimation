# 드론 자료 선택 기준

사용자의 2026-10-06 지시에 따라 **조종기 클래스는 연구의 학습·검증·평가에서 제외**한다. 드론과 조종기를 별도의 출력 신호원으로 함께 세지 않는다.

2026-10-07 추가 지시에 따라 **영상전송 여부는 자료 편입 조건으로 사용하지 않는다.** 기체 측에서 송신된 텔레메트리, 위치·상태 정보, 제어 명령에 대한 응답, 식별 방송, 영상 등은 모두 연구 대상이다. 이는 각 기능의 신호가 RFUAV에 실제 수록됐다는 주장이 아니다. FHSS/OFDM 같은 파형 형태와 신호 기능도 구분한다.

37범주 전체를 실제 송신원 기준으로 검토한다. 기존 6범주도 기체 단독 송신 검증이 끝난 것으로 취급하지 않는다. 기체 측으로 확인된 기록은 기능과 무관하게 후보가 되고, 조종기 측 송신으로 확인된 기록은 제외한다. 방향 미확인 또는 양방향이 섞인 기록은 그 상태를 유지하며 기체 단독 정답으로 바꾸지 않는다. 스펙트럼 폭·호핑·주기성만으로 송신 방향을 확정하지 않는다.

OFDM, LoRa/CSS, 주파수 도약 등 서로 다른 파형 계열을 검토 범위에 둔다. [Semtech 설명](https://www.semtech.com/lora/what-is-lora)에서 LoRa는 CSS 기반 변조이며, 영상 같은 서비스 종류와 다른 분류 축이다. 사용자가 말한 `firecross`가 TBS Crossfire를 뜻한다면 해당 링크의 기체 측 전송도 같은 기준으로 검토할 대상이다. 구체적인 프로토콜 이름과 개별 녹음의 변조 방식은 제품명만으로 부여하지 않는다.

확인한 로컬 RFUAV XML의 중심 주파수는 2.41–2.47GHz 또는 5.76–5.8GHz이며 전부 100MS/s다. [TBS 공식 자료](https://www.team-blacksheep.com/new-support/kb/4000134179/)의 Crossfire 868/915MHz 기록을 이 목록에서 확보했다고 주장하지 않는다. 다른 외장 자료의 실제 수록 범위는 따로 확인한다. 서로 다른 RF 대역을 옮겨 합성하면 기저대역 합성 실험으로 표시한다.

파형 계열 확장에서는 시간 문맥뿐 아니라 점유 대역폭과 표본률을 함께 맞춘다. 광대역용 특징의 주파수 평균으로 협대역 성분을 지우지 않는지 확인하고, 더 긴 호핑·패킷 구조에 필요한 관측 시간도 측정한다. 기종·파형 계열·실제 국소 전력별 복원 지표를 남긴다. 이는 후속 검증 규칙이며 현재 TCN의 범용성 검증 완료를 의미하지 않는다.

RFUAV 드론 후보는 DAUTEL EVO NANO(자료 원래 표기), DJI AVATA2, DJI FPV COMBO, DJI MAVIC3 PRO, DJI MINI3, DJI MINI4 PRO다. Mavic 3 Pro와 기존 DRFF-R2의 Mavic 3는 별도 기종이다. DRFF-R2 자료는 기존 연구 범위와 파일 사용 이력을 함께 관리한다.

**2026-10-07 범위 정정:** 위 6범주는 초기 기체명 허용 목록이지 RFUAV에서 사용 가능한 기체 측 신호의 총수 검증 결과가 아니다. 원문 표 4는 Herelink HX4와 YunZhuo H16에도 영상전송 대역폭을 기재한다. 두 로컬 범주의 12파일은 송신원 확인 후 편입 여부를 결정할 추가 후보로 복원한다. 논문의 PARROT은 로컬 폴더와 현재 저자 공개 RAR 목록에 없다. 논문에는 없고 공개본에는 있는 JR PROPO XG14 때문에 목록의 총수는 모두 37이어도 구성이 다르다. [37범주 대조와 정정 근거](../reports/2026-10-07/RFUAV_SCOPE_CORRECTION_KO.md).

제품에 air unit이 있다는 사실이나 영상전송 대역폭 표기만으로 해당 로컬 기록 전체를 기체 단독 정답으로 승인하지 않는다. 기존 5종 시간 문맥 대조의 봉인된 자료·스냅샷·보류 Autel은 유지하고, 추가 후보는 별도 편입 명세로 검토한다.

같은 이유로 영상전송 칸이 비어 있는 범주도 자동 제외하지 않는다. 기존 범위 대조의 영상전송 8범주라는 수는 메타데이터 집계일 뿐 연구 대상의 상한이 아니다. 후속 메타데이터 검토 목록은 미편입 31범주 전체에 송신원 확인을 요구하며, 영상전송 기재 여부는 별도 정보로만 보존한다.

## 기록 단위와 중복

`pack*_0-1s.iq` 등은 긴 기록의 조각이다. XML과 같은 디렉터리의 원기록 묶음 전체를 한 역할에 배정한다. 같은 묶음의 조각을 train/test로 나누지 않는다. 기록 묶음이 다르다는 사실만으로 다른 날짜·다른 물리 기체라고 주장하지 않는다. RFUAV의 SerialNumber는 자료 묶음 번호이며 물리 기체 일련번호가 아니다.

Mini 3의 VTSBW=10 폴더에는 `pack1.xml`과 `pack2_*.iq`가 함께 있다. 이 불일치를 보존하며, 같은 폴더에 XML이 하나뿐일 때 디렉터리 단위의 잠정 대응으로 기록한다. 드론 후보 131파일의 앞·중간·끝 각 16,384 복소 표본(합계 약 51.5MB)을 확인했고 비유한 값과 세 구간 지문이 모두 같은 파일 쌍은 없었다. 전체 파일 동일성·시간 이동/배율 유사성까지 배제한 결과는 아니다. Autel 후보 13파일의 파형은 이 검사에서 읽지 않았다.

후속 CPU 검사에서는 개발 후보 131파일 전체 SHA-256을 계산했고 같은 해시를 갖는 파일은 없었다. 393개 캐시의 전체 내용·전력을 재검산했다. 학습/검증 캐시의 처음 8,192표본을 ±1,024표본 범위에서 비교한 35,856쌍에서 높은 이동 유사도는 없었다. 이 제한 검사는 모든 시차·주파수 이동의 중복 검사나 수집 세션 독립성 확인을 대신하지 않는다. [검사 완료 보고](../reports/2026-10-06/CPU_COMPLETED_KO.md).

## 송신원 의미

드론 기종 폴더를 고르는 것과 그 기록의 모든 표본이 드론 본체에서만 송신됐음을 입증하는 것은 다르다. RFUAV 원문은 조종 신호와 영상 전송을 함께 설명한다. 따라서 기종 폴더만으로 기체 전용 송신원 정답이나 실제 드론 대수를 단정하지 않는다. 조종기 단독·명시적 결합 라벨은 제외하고, 방향 또는 단독 송신 여부가 불명확한 자료에는 그 상태를 표시한다. 실제 기체 수를 주장할 평가는 수집 설명/주석으로 별도 확인한다.

2.4GHz와 5.8GHz 기록의 복소 기저대역을 합치면 주파수 기준을 바꾼 **합성 기저대역 중첩**이다. 이것을 원래 RF 대역에서 실제 동시 수신한 결과로 표시하지 않는다. 같은 대역 합성과 대역을 바꾼 스트레스 검사를 나누어 보고한다. 샘플레이트 변환은 필요할 때 대역 제한 필터와 함께 적용한다.
