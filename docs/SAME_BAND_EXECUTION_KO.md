# 같은 대역 주 실험 우선 실행

2026-10-07: RFUAV 단일 데이터셋·같은 대역이라는 최신 사용자 조건을 우선한다. 기존 탐색 비교의 25 epoch 단계 결과와 optimizer/RNG를 포함한 재개 체크포인트를 보존한 뒤 새 주 실험을 실행한다. 기존 50 epoch 예산을 완료했다고 표시하거나 기존 가중치를 새 주 실험에 전달하지 않는다.

## 실행 순서

1. 기존 시간 순서 TCN·평균 문맥 대조 양쪽의 25 epoch 단계 평가·선택 체크포인트를 기다린다.
2. 기존 실행기의 PID·시작 시각·명령줄을 확인해 스케줄러만 교체한다. GPU 학습기는 두 군의 25 epoch 단계가 저장될 때까지 유지한다.
3. GPU 학습기를 잠시 정지하고 마지막 체크포인트의 epoch·업데이트 수·실험 해시와 완료 기록의 일치를 확인한다. optimizer/RNG를 포함한 LAST 파일 두 개를 복사·해시 검산한 후 해당 학습기만 종료한다. 저장 전인 다음 epoch의 계산은 재개할 때 반복한다.
4. 같은 대역 실험의 원 규모 GPU 순전파·역전파 검사를 수행한다. 동일 초기화와 시간 경로의 기울기를 확인한다. 실패 시 임의 축소하거나 자동 재시작하지 않는다.
5. 새 초기화에서 U-Net+TCN 두 군의 같은 대역 비교를 실행한다. 3개 고정 혼합의 학습 가능성 검사에 사용한 가중치는 폐기하고, 본 비교를 seed 0 초기화에서 시작한다.
6. 새 비교 완료 후 기존 탐색 비교를 원래 체크포인트에서 50 epoch까지 재개하고, 기존에 보류한 native RF 비교·평가를 잇는다. detector 및 DR-NMF D2는 재개하지 않는다.

## 새 비교 규약

- RFUAV 5개 학습 기종, 원기록 묶음별 학습/검증 분할, 보류 Autel은 그대로 유지한다.
- 100MS/s. 2.4GHz끼리 또는 5.8GHz끼리만 기저대역 중심을 맞춰 합성한다. 같은 대역이어도 실제 RF 중심 차이를 그대로 재현한 것은 아니다.
- 전체 모델 규모와 학습 설정은 이전 시간 문맥 비교와 같다. 짧은 약 0.64ms 복소 STFT 경로에 약 21ms의 혼합 전력·주파수 특징을 TCN으로 연결한다. 긴 경로가 전체 구간의 복소 위상을 보존하는 구조는 아니다.
- epoch당 2,400개, 유효 배치 32, 75업데이트, 최대 50 epoch/군당 3,750업데이트. 새 고정 검증 630개를 두 군에 공통 적용한다. 5/10/25/50 epoch 단계별 선택 규칙도 동일하다.
- CPU 특징 준비는 학습 진행보다 최대 두 epoch 앞서가며, 낮은 CPU/I/O 우선순위를 사용한다. 기존 CPU 작업도 자신의 진행 기록에 맞춰 대기하므로 불필요하게 50 epoch분을 모두 생성하지 않는다.
- 단일 GPU 공유 잠금과 실제 GPU 프로세스/메모리 검사를 적용한다. 기존/신규 데이터·학습 스냅샷은 수정하지 않는다.

이번 실행 순서 변경은 사용자가 지정한 새 실험 조건에 자원을 우선 배정하는 결정이다. 초기 결과가 유리한 조건을 골라 새 분할을 만든 변경은 아니다. 기존/신규 검증 사례가 다르므로 두 결과를 직접 성능 대조하지 않는다. 성분 수는 합성 기록 기여 수이며 실제 물리 드론 대수 검증은 별도다.

## 실제 전환과 자원 검사 보완

2026-10-07 오전 두 군의 25 epoch 저장과 재개 파일 복사·검산을 완료했다. 새 화면 공유 RustDesk 프로세스가 기존 GPU 허용 목록에 없어 자원 대기가 발생했다. 기존 봉인된 자원 규약을 수정하지 않고, 해당 프로세스의 정확한 PID·시작 시각·명령줄·실행 파일과 256MiB 상한을 확인하는 별도 실행 검사를 적용했다. 다른 GPU 프로세스, 장치 변경, 메모리 부족은 계속 거부하며 화면 공유 프로세스에 신호를 보내지 않는다. 별도 실행 규약과 체크포인트를 검산한 뒤 GPU 사전 검사를 통과했다. 이 보완은 데이터·모델·학습 예산을 변경하지 않는다.
