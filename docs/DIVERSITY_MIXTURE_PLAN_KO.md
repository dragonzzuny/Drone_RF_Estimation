# 같은 데이터셋·같은 대역의 I/Q 분리 실험

2026-10-07 최신 사용자 지시를 반영했다. 유효한 명세는 `within_dataset_selection_20261007_v3`이다. 데이터셋을 합친 최초 후보 명세는 후속 학습에 사용하지 않는다.

## 목표와 자료

혼합 I/Q만으로 1–3개 기록 성분의 복소 파형을 복원하고, 새로운 원기록·기종에서 성능이 유지되는지 확인한다. 원 규모 U-Net에 긴 시간 문맥을 연결한 모델과 동일 파라미터의 시간 평균 대조를 같은 초기화·혼합 목록·업데이트 예산으로 비교한다. 조종기 클래스는 제외하고 영상전송 여부만으로 자료를 제한하지 않는다.

**주 실험은 RFUAV 단일 데이터셋이다.** DroneDetect는 자체 자료만으로 독립 재학습·평가하는 보완 후보로 둔다. 두 데이터셋의 파형·학습 집합·가중치를 합치지 않는다.

| 독립 실험 | 학습 기종 또는 원자료 코드 | 보류 기종 | 합성 범위 |
|---|---|---|---|
| RFUAV, 5.8GHz | DJI AVATA2, FPV COMBO, MAVIC3 PRO | Autel EVO Nano | 서로 다른 학습 기종 1·2·3개 |
| RFUAV, 2.4GHz | DJI MINI3, MINI4 PRO | 현재 별도 미학습 기종 없음 | 서로 다른 학습 기종 1·2개 |
| DroneDetect 독립 보완 후보, 2.4GHz | AIR, INS, MIN, MP1, MP2, PHA | DIS: Parrot Disco | 자체 기록 1·2·3개 |

RFUAV는 학습 8묶음/83파일, 검증 5묶음/48파일, Autel 보류 1묶음/13파일 배정을 유지한다. 허용 학습 조합은 단일 5개·두 성분 4개·세 성분 1개다. 세 성분 조합은 AVATA2+FPV COMBO+MAVIC3 PRO다. 2.4GHz의 같은 기종 창을 복제해 세 기종으로 세지 않는다. Autel 보류 평가 조합은 단일 1·두 성분 3·세 성분 3개이며 모델 선택에 사용하지 않는다.

DroneDetect는 폴더 코드를 기준으로 배정한다. MP1/MP2는 파일명 접두사와 폴더 코드가 달라 파일명만으로 재분류하지 않는다. 알려진 6코드의 CLEAN 85파일 중 반복 번호 0–2의 51파일은 학습 후보, 3의 17파일은 검증 후보, 4의 17파일은 확인용이다. DIS 40파일 전부를 새 분리기 학습에서 제외하며 그중 CLEAN 10파일이 미학습 기종 평가 후보다. MP1+MP2 및 이를 포함하는 세 성분 조합 4개는 학습·검증 혼합에서 보류한다. 이 제약 후 단일 6·두 성분 14·세 성분 16개 학습 조합이 남는다. 이전 탐지 연구의 자료 노출 이력이 있으므로 연구팀 전체가 처음 보는 자료라고 부르지 않는다. 반복 번호가 다른 것이 독립 수집 날짜를 뜻하지도 않는다.

## 수신 조건과 합성 통제

1. **데이터셋 고정:** 다른 데이터셋이면 같은 표본률로 바꿨어도 혼합 생성기가 거부한다. 한 모델의 학습 집합에도 다른 데이터셋을 합치지 않는다.
2. **대역 고정:** 수신 중심주파수 메타데이터로 2.4GHz끼리 또는 5.8GHz끼리만 합성한다. 기종명만으로 판단하지 않는다.
3. **원래 표본률 유지:** RFUAV 100MS/s, DroneDetect 보완 후보 60MS/s. 이전 60→100MS/s 캐시는 형식 검사에서만 사용했다.
4. **수신 설정 확인:** RFUAV 후보 14묶음의 XML은 DeviceType=USRPX310, SampleRate=100MS/s, IFBandwidth=100MHz다. ScaleFactor와 ReferenceSNRLevel은 묶음마다 다르다. XML SerialNumber는 수신기 물리 개체의 동일성 증거로 쓰지 않는다. [RFUAV 원문 4.1절](https://arxiv.org/html/2503.09033v2#S4.SS1)은 X310 수집·재생 구성을 설명한다.
5. **대역 내 위치:** 첫 비교는 같은 대역 안에서 기저대역 중심을 맞춘 합성이다. 원래 RF 중심주파수 차이를 보존했다고 주장하지 않는다. 중심 차이를 유지하는 후속 검사에서는 공통 관측 대역·필터를 정답에도 동일하게 적용한다. 시간·주파수 점유 중첩도와 활동량을 따로 기록한다.

같은 데이터셋이라도 수집 설정과 잡음이 모두 같은 것은 아니다. 기록 묶음 분할, 수신 설정, 국소 전력, DC와 잡음 특성을 함께 검토한다. 기존 RFUAV 검증은 학습과 영상전송 대역폭도 달라 그 영향을 구분해 보고한다. 대역명이 같다는 사실만으로 시간·주파수 중첩을 입증하지 않는다.

## 학습·평가

- 전체 약 20.97ms 구간에서 성분 전력을 정하고 위상·시간 위치를 바꾼 뒤 짧은 창을 추출한다. 창마다 성분 전력을 다시 맞추지 않는다. 이는 입력 구성이고 성능 개선이 입증된 전처리는 아니다.
- 두 성분은 −10/0/+10dB, 세 성분은 동일 전력과 각 성분이 10dB 약하거나 강한 7조건이다. 설정 전력과 실제 창의 전력비를 모두 남긴다.
- RFUAV 비교는 seed 0, 원 규모 U-Net+TCN, 최대 50 epoch, epoch당 2,400개 합성 예제, 유효 배치 32, 군당 최대 3,750업데이트다. 5/10/25/50 epoch에 보고한다. 두 군의 고정 검증 630개는 동일하다. 이전 대역 간 합성을 포함한 검증 630개와는 다르므로 옛 수치를 직접 대조하지 않는다.
- NMSE, 절대 SI-SDR, 혼합 대비 개선량, STFT 크기 오차, 모든 성분이 함께 개선된 비율을 보고한다. 대역·성분 수·약신호 방향을 나눠 본다. 파형 개선 후 식별 효과를 따로 평가한다.
- 개수 정확도·MAE·혼동행렬의 정답은 합성에 더한 **기록 성분 수**다. 실제 드론 대수나 기체 단독 송신원 주석으로 바꾸지 않는다. DroneDetect CLEAN도 조종기 링크가 전혀 없다는 뜻은 아니다. [수집 설명](https://www.mdpi.com/2226-4310/9/12/738)은 기체와 조종기가 함께 있는 환경을 기술한다.

## 현재 단계와 후속 실행

같은 데이터셋·대역의 RFUAV 학습 목록 120,000개(50 epoch분)와 검증 목록 630개를 준비하고 모든 행의 대역·역할을 검사했다. 이는 독립 원기록 수가 아니다. CPU에서 검증 및 첫 두 epoch의 문맥 특징을 별도 스냅샷으로 준비한다. 새 GPU 본 학습은 아직 시작하지 않았다.

기존 GPU의 RFUAV 5종 시간 문맥 대조는 이전 봉인 조건으로 실행 중이다. 대역 간 기저대역 합성을 포함하므로 새 주 실험 결과로 이름을 바꾸지 않는다. 첫 중간 평가에서 계속 실행할 가치와 새 주 실험의 우선순위를 판단한다. 새 GPU 실행 전 사전 검사·실행 규약을 고정한다.

DroneDetect 학습 후보 51파일의 앞부분 I/Q 형식과 복소 합성 입력 검사를 마쳤다. 이 짧은 구간의 DC 전력 비중 중앙값은 38.60%, 43/51구간은 10%를 넘었다. 이를 모두 수신기 오프셋으로 단정하지 않고 변동 성분·다른 시간 구간을 추가 확인한다. 새 학습 편입은 하지 않았다. 60MS/s에서 물리 시간을 맞춘 독립 로더가 필요하다.

LoRa/Crossfire는 지정된 로컬 자료 이름·ZIP 목록·SigMF 메타데이터 검색에서 확인되지 않았다. 이름 없는 파형의 존재까지 부정한 결과는 아니다. [OSU 공개 LoRa](https://research.engr.oregonstate.edu/hamdaoui/datasets)는 별도 IoT 실험 자료이며 드론 정답으로 대신 쓰지 않는다. Crossfire는 검증된 I/Q 수록 근거 확보 전 편입하지 않는다.
