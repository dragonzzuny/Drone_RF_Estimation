# 최대 세 기록 성분의 시간 문맥 대조 실행 규약

2026-10-06. 사용자의 목표 달성 계속 지시에 따라 준비한 전체 크기 U-Net을 실제 GPU 대조로 연결한다. 이번 질문은 **같은 혼합 자료에서 시간에 따른 문맥 변화를 제공하면 기록 성분의 복원 오차가 줄어드는가**이다. Transformer·LSTM은 구현을 보존하되 이번 첫 비교에는 넣지 않는다.

## 비교와 예산

| 항목 | 고정 조건 |
|---|---|
| 비교군 | ordered TCN / 같은 TCN에 시간 평균 문맥을 반복해서 제공하는 mean 대조 |
| 규모 | 두 군 모두 32,142,859 파라미터, 전체 64/128/256/512/1024 U-Net |
| 입력·출력 | 약 21ms 혼합 문맥 + 0.63872ms 복소 복원 창; 3성분과 배경 출력 |
| 초기화 | seed 0의 동일 가중치; 이전 DRFF/NMF 가중치 사용 안 함 |
| 학습 | 군별 최대 50 epoch, epoch당 2,400예제, 유효 배치 32, 75업데이트/epoch |
| 개수 구성 | 각 epoch에서 합성 기록 수 1/2/3을 각 800예제로 균등 배정 |
| 총 예산 | 군별 120,000예제, 3,750업데이트; 두 군에 같은 목록 |
| 최적화 | AdamW, LR 1e−4, weight decay 1e−4, gradient norm clip 1, float32, microbatch 1 |
| 손실 | 세 슬롯 PIT NMSE+coherence와 배경 손실 + 합성 기록 수 CE의 0.1배 |
| 검증 | 원기록 묶음을 분리한 고정 630조건; 각 개수 210조건 |
| 선택 | 1/2/3개별 평균 성분 NMSE를 다시 평균한 값의 최소; 초기 epoch 0도 후보 |
| 시점 | 매 epoch 검증, 5/10/25/50 epoch에서 선택 모델·조건별 지표·예시 출력 보존 |

시간 평균 대조는 시간 순서와 위치별 변화를 모두 없앤다. 따라서 우월성이 관찰되어도 주기성만의 인과 효과로 주장하지 않는다. 두 군은 같은 파라미터 수이므로 추가 용량의 효과와 시간 변화 제공 효과를 구분하는 데 도움이 된다. 홀수 epoch는 ordered 먼저, 짝수 epoch는 mean 먼저 실행한다. GPU에서 동시에 두 군을 학습하지 않는다. CUDA 연산의 완전한 비트 단위 결정성은 주장하지 않는다.

## 데이터 해석과 개발 비교 편입

기존 감사한 RFUAV 학습 8묶음·83파일·249캐시, 검증 5묶음·48파일·144캐시를 그대로 사용한다. 정확 복제 및 제한한 이동 유사도 검사 결과를 유지하고, 조종기·명시적 결합 라벨은 제외한다. 원기록 묶음 이후 창과 혼합을 생성한다. Mini 3의 pack1 XML/pack2 IQ 명칭 차이는 같은 디렉터리의 유일한 XML 대응으로 명시한다. 다른 물리 기체·날짜를 확인했다는 뜻은 아니다.

이제 이 자료를 **이 한계가 명시된 개발 대조**에 편입한다. 기존 원자료 manifest의 잠정 상태를 덮어쓰지 않고 새 PREPARATION.json에 이 비교의 허용 범위·목록 해시·전력 처리·선택 규칙을 기록한다. 수집 송신원 불명확성을 해결했다고 선언하지 않는다. 검증은 다른 기록 묶음이지만 대역폭 조건도 달라져 있으며 독립 날짜 시험으로 부르지 않는다. 보류한 Autel 및 기존 DRFF 확인용 6파일은 개봉하지 않는다.

긴 캐시 전력으로 각 성분의 배율을 정하고 위상을 무작위화한 뒤 복소수로 합성한다. 거기서 짧은 복원 창을 뽑으며 창별 재정규화는 하지 않는다. 이는 이번 데이터 생성 조건이며, 기존 DRFF에서 전력 보존 방식이 개선되지 않았다는 결과를 바꾸지 않는다. 서로 다른 원 RF 중심 주파수의 겹침은 **주파수 기준을 바꾼 합성 기저대역**이다. 같은 기종 여러 대와 실제 세 대 동시 수신은 이번 비교에서 검증하지 않는다.

두 성분의 전력차는 −10/0/+10dB다. 세 성분은 동일 전력과 각 성분을 번갈아 10dB 약하게/강하게 설정한 7조건이다. 학습에서는 개수별 800개 안에서 기종 조합·전력 조건을 순환 배정하고 epoch에 따라 시작 위치를 옮긴다. 매 epoch 각 세부 조건이 완전히 같은 횟수인 것은 아니다. 검증은 모든 단일/두 기종/세 기종 조건에 정수 반복을 주어 개수별 210개를 만든다.

## 개수 정답의 구분

원기록의 활동·송신원 주석이 충분하지 않아 **물리 드론 대수용 `count_eligible=False`는 유지**한다. 이를 자동으로 True로 바꾸지 않는다.

이번에는 합성 수식으로 정확하게 아는 `construction_count`를 별도 보조과제의 정답으로 쓴다. 이는 **더한 기록 성분 수**다. 긴 구간에 드론 송신이 거의 없는 경우에는 관측으로 구별하기 어려울 수 있으며, 기록마다 포함된 수신 잡음도 각 성분의 일부다. 따라서 해당 정확도를 실제 활동 송신원 수나 실제 드론 대수 정확도로 바꾸어 말하지 않는다. 개수 CE를 기존 물리 개수 eligibility API와 분리해 구현했다.

개수 정확 일치율·MAE·혼동행렬은 1/2/3 균등 자료에서 다수 클래스 기준 1/3과 함께 보고한다. 복원은 각 개수·실제 국소 전력·약한 성분 위치별로 보고한다. 개수 예측으로 파형을 즉시 잘라내거나 정답 개수를 모델 입력에 주지 않는다. 0개 및 4개 이상은 이번 개수 분류 범위가 아니다.

## 시작 전·중간·종료 확인

1. **CPU 검사:** 역할 분리, 같은 합성의 긴/짧은 입력 일치, 위상 상쇄, STFT 왕복, 손실·역전파, 개수 순열, 신호를 건드리지 않는 실행 인수 규칙을 검사한다.
2. **전체 입력 GPU 사전 검사:** 축소 없는 두 모델을 실제 63,872표본으로 순전파·역전파한다. 1/2/3개 예제에서 유한 손실·문맥 경로 gradient·메모리·시간을 기록한다. 이 최적화 결과는 폐기한다. 실패 시 CPU 학습이나 작은 모델로 자동 변경하지 않는다.
3. **소수 혼합 적합 진단:** 학습 목록의 첫 1/2/3개 예제에 전체 모델을 48업데이트 적합한다. 평균 파형 손실이 감소하지 않으면 긴 학습 전에 중단하고 원인을 확인한다. 감소해도 일반화 성공이 아니다. 진단 가중치는 폐기하고 본 비교는 같은 원 초기화에서 시작한다.
4. **본 대조:** 같은 목록으로 매 epoch 두 군을 이어서 학습하고 모델·옵티마이저·RNG를 저장한다. 비유한 손실·파일 변경·CPU worker 오류는 실패로 기록하며 무조건 재시작하지 않는다.
5. **검증 및 보존:** 세 출력 전체에 하나의 PIT 순열을 적용한 I/Q NMSE, 평균 제거 후 복소 배율 불변 SI-SDR, 혼합 대비 개선량, 비활성 슬롯 누출, 출력 합 오차를 기록한다. 이는 독립 짧은 평가 창 단위다. 긴 전체 파형의 창 간 추적 완료를 뜻하지 않는다.

1개 성분에서는 혼합 자체가 정답이므로 양의 SI-SDR 개선을 성공 조건으로 삼지 않는다. 해당 조건은 파형을 얼마나 보존하는지 NMSE로 평가한다. 2/3개 조건에서는 가장 약한 성분과 모든 성분의 개선 여부를 함께 보고한다. 초기 성과를 전체 평균 하나로 판단하지 않는다.

평가 NMSE·SI-SDR은 복소 배정밀도로 계산한다. 0 또는 상수 출력의 SI-SDR은 정의되지 않은 상태로 기록하며 작은 상수를 넣어 유효한 0dB 점수로 바꾸지 않는다. 비유한 점수가 포함된 조건은 해당 평균과 유효성 개수를 함께 명시한다.

각 단계의 선택 체크포인트를 따로 보존해 이후 BEST.pt가 바뀌어도 같은 결과를 재현할 수 있게 한다. 예시 출력은 성능을 보기 전 정한 **각 개수의 첫 검증 사례**를 저장한다. 나머지 630조건의 수치는 전체 남기며 고정한 체크포인트·자료로 재생성할 수 있다.

## 실행 순서와 CPU 병행

현재 진행 중인 기존 N 크기 손실 worker의 PID·시작 시각·명령을 확인한 뒤 **감시 제어기만 인수**한다. worker에는 신호를 보내거나 재시작하지 않는다. 이전 동결 소스·가중치·옵티마이저는 변경하지 않는다.

순서는 기존 크기 손실 50 epoch와 저장 출력 검산 → 기존 창 병합 270조건과 검산 → 새 전체 입력 GPU 검사·고정 혼합 진단·시간 문맥 2군 비교 → 보존된 native RF Transformer 원 비교 재개다. native 비교는 취소·완료로 표시하지 않고 새 목표 뒤로 순서만 옮긴다. 중단 지시된 detector와 DR-NMF D2는 유지한다.

CPU 14·15번, nice +10, 낮은 I/O 우선순위로 문맥 특징을 준비한다. 공통 검증 특징과 두 학습 epoch까지만 먼저 만들고, 이후에는 두 군의 공통 완료 epoch보다 최대 2개 앞서 준비한다. GPU와 다른 작업의 자원을 중복 점유하지 않도록 기존 GPU 입장 검사와 공유 lock을 유지한다. 모든 긴 worker는 소스 스냅샷에서 실행한다.

비교 규칙에는 기존 experimental-design 절차를 이어서 적용했다. 절차 출처는 [전체 계획의 방법 근거](PLAN_KO.md#방법-근거와-작성-절차)에 기록되어 있다. 이는 분리 성능의 근거가 아니다.
