# 매epoch 완료 PC 알림

**2026-10-11 변경:** 사용자 지시로 기존 SepTDA·개별 후보 학습과 기존 알림 관찰기를 중지했다. 현재 통합 모델의 완료epoch는 `experiments/integrated_notifications_20261011/watch.py`가 알린다. 상태는 `local/integrated_notifications_20261011_v1/STATE.json`이다. 검증 파일 지문을 검사하고 같은 세 파형 지표를 표시하며, 등록된 조기 종료까지 보고하면 종료한다. 이하 설명과 알림 이력은 이전 다섯 후보 실행 당시 기록이다.

2026-10-10 사용자의 반복적인 epoch별 보고 요청에 따라, 학습 PC의 GNOME 알림 센터에 실제 완료 결과를 전달하는 별도 관찰 프로세스를 실행했다. 대화 응답이 진행 중이 아니어도 이 프로세스는 동작한다. 채팅 자동 발송 기능은 아니다.

알림 이름은 **Drone RF 학습**이다. SepTDA 참고 → 본체 고정 시간·주파수 보강 → 시간 순서 게이트 → 성분 상호작용 → 파형 업데이트 보호의 새 완료구간을 각각 알린다. 각 알림에는 두·세 신호의 NMSE·복소SI-SDR·최약NMSE, 직전 구간 대비 NMSE 변화, 선택 가중치를 넣는다. 학습 손실만으로 개선을 표시하지 않는다.

4epoch 결과를 첫 알림으로 실제 발송해 로컬 알림 서버의 응답을 받았다. 이는 사용자가 화면을 읽었다는 확인은 아니다. 당시 데스크톱 배너 표시 설정은 켜져 있었다. 자동 사라짐 없음으로 요청했지만 실제 표시·보관 동작은 GNOME 설정을 따른다.

관찰기는10초마다 저장된 epoch 완료 파일을 읽고 검증 파일 지문을 확인한다. 원 I/Q, GPU, 학습 코드·순서·모델·optimizer는 건드리지 않는다. 새 알림 성공 후 완료구간을 저장하므로 재실행 시 이미 기록한 구간을 반복 발송하지 않는다. 알림 직후 상태 저장 전에 프로세스가 중단되면 한 알림이 중복될 수 있다. 알림 서버 연결 실패는 상태에 남기고 재시도한다. PC 로그인 세션과 관찰 프로세스가 필요하며 부팅 자동 등록은 하지 않았다.

실행 코드: `experiments/epoch_notifications_20261010/notify_epochs.py`.

로컬 상태·알림 이력: `local/epoch_notifications_20261010_v1/STATE.json`; 실행 로그: 같은 폴더의 `worker.log`. 상태의 `seen`은 **데스크톱 알림 완료** 구간이며 채팅 보고 완료 구간과 다르다. 채팅이 활성화되면 누락된 완료 결과를 확인해 직접 보고한다.

모든 후보50구간을 보고한 뒤 관찰기는 종료한다. GPU 학습과 순차 큐는 원래의 독립 프로세스로 계속 동작한다.
