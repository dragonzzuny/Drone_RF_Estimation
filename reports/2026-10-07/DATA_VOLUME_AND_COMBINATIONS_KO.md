# 지도 파형 복원에 필요한 데이터 확대

2026-10-07. 현재 분리기는 **지도학습**이다. 입력은 두세 원기록의 복소 합이고, 정답은 합성에 사용한 각각의 I/Q 기여 파형이다. 추론에는 정답을 넣지 않는다. 학습 조합을 많이 생성했다는 사실과 서로 다른 원파형을 충분히 사용했다는 사실을 구분한다.

## 확인한 병목과 실행한 조치

현재 RFUAV 학습 캐시는 각 원본 파일의 세 위치에서 약 20.97ms씩 추출했다. 원본 전체를 해시 검사했지만, 전체 파형을 학습에 사용한 것은 아니었다.

| 항목 | 현재 학습 자료 | 확대 준비 목표 |
|---|---:|---:|
| 원본 학습 파일 | 83 | 같은 83파일 |
| 원기록 묶음 | 8 | 같은 8묶음 |
| 기종 | 5 | 같은 5기종 |
| 이용 가능한 원본 시간 합계 | 81.2684초 | 81.2684초 |
| 학습 캐시가 담는 고유 시간 | 5.2219초 | 81.2684초 |
| 원본 시간 대비 범위 | **6.43%** | **100%** |
| 약 20.97ms 문맥 구간 | **249** | **3,902** |

독립적으로 녹음한 기체나 세션이 늘어나는 작업은 아니다. **기존 학습용 원본의 사용하지 않았던 시간 구간을 활용하는 작업**이다. 마지막 구간은 파일 끝을 포함하도록 앞 구간과 일부 겹친다. 그래서 문맥 수를 곱한 시간 대신 원본 내 구간 합집합으로 고유 시간 범위를 계산한다. 확대 목표는 데이터 준비 범위이며 아직 모델이 모두 학습했다는 뜻이 아니다.

CPU 준비 worker를 실제 실행했다. 13:47경 확인 시 83파일 중 14파일의 원본 해시 재검산을 마쳤고 다음 파일을 읽으면서 649개 구간을 생성했다. 약 60.97GiB의 새 캐시를 별도 경로에 준비한다. 기존 GPU는 고정된 비교를 계속하며, 새 자료를 진행 중인 학습 목록에 끼워 넣지 않는다.

수행하는 검사는 다음과 같다.

- 모든 원본 바이트의 SHA-256을 기존 감사 결과와 대조한다.
- 파일 끝부분까지 빠짐없이 포함하면서 복소 I/Q의 바이트 값을 보존한다. 정규화·리샘플링을 적용하지 않는다.
- 무한대·NaN을 검사하고, 전력·DC·국소 전력 통계를 저장한다. 전력이 0인 구간은 기록을 남기며 성분 전력 정규화에 적합하다고 승인하지 않는다.
- 기존 검증 캐시 144개는 동일한 파일·구간·정답을 유지한다. 새 학습 구간과 기존 검증 캐시의 제한된 시차 유사도 및 정확한 복제를 확인한다. 고상관은 독립성 증명이나 복제 확정으로 단정하지 않고 검토 대상으로 남긴다.
- Autel 보류 I/Q와 확인용 원기록을 읽지 않는다. 학습 준비 완료와 GPU 학습 편입은 별도 상태로 기록한다.

## 기종 조합은 왜 적었고 무엇을 늘릴 수 있는가

현재 2.4GHz 학습 기종은 2개, 5.8GHz 학습 기종은 3개다. **같은 대역·서로 다른 기종만 허용한 현재 구성에서는** 두 성분이 C(2,2)+C(3,2)=4조합, 세 성분이 C(3,3)=1조합으로 이미 전부다. 단순히 조합 생성기를 더 돌려 다른 기종 조합이 생기는 구조는 아니다.

확장은 세 방향을 구별한다.

1. **실제 원파형 구간 확대 — CPU 실행 중.** 같은 기종 조합이라도 다른 패킷·활동·진폭·위상 구간을 사용하도록 원자료 범위를 넓힌다. 이후의 합성에서는 서로 다른 파일·구간과 시간 위치를 충분히 바꾼다. 성능 효과는 동일 검증·동일 업데이트 예산으로 평가한다.
2. **같은 기종의 서로 다른 기록을 합성 — 후보 목록 작성 완료, 학습 미편입.** 예를 들면 서로 다른 파일의 Avata 2+Avata 2, Avata 2+Avata 2+FPV Combo다. 순서를 구분하지 않고 중복 기종을 허용하면 두 성분 구성은 9종, 세 성분 구성은 14종까지 가능하다. 각 구성에 필요한 서로 다른 원본 파일이 학습·검증 역할 안에 있는지 확인했다. 현재 봉인 로더는 중복 기종을 거부하므로 별도 로더·분할 검사가 필요하다. 같은 파일을 그대로 복제해 더하지 않으며, 같은 기종의 서로 다른 물리 기체를 측정했다고 주장하지 않는다.
3. **실제 기종·송신기 다양성 확대 — 송신원 확인 후 편입.** RFUAV 37범주에는 조종기 송신이 포함된다. 전체 범주를 기체 37종의 정답 파형으로 넣을 수는 없다. 원문도 원격 조종기의 FHSS 송신을 수록한다고 설명한다. [RFUAV 원문 4.1절](https://arxiv.org/html/2503.09033v2#S4.SS1). Herelink HX4·YunZhuo H16 등은 추가 검토 후보이며, 현재 로컬 녹음의 기체 측 송신 여부가 확인된 신규 학습 자료는 아니다. 영상 신호 유무만으로 편입 여부를 결정하지 않는다.

Autel을 학습으로 옮겨 조합 수를 늘리면 미학습 기종 검증 역할이 사라지므로 현재 역할을 유지한다. 지도학습이라고 모든 가능한 조합을 학습에 넣어야 하는 것은 아니다. **보지 않은 기록·조합에서도 분리되는지 평가할 자료를 남기는 것**이 목표와 맞는다.

외장하드의 DroneDetect는 별도 단일 데이터셋 실험 후보로 검토한 6개 학습 코드가 같은 2.4GHz에 있다. 서로 다른 기종의 두 성분 15조합·세 성분 20조합 중 보류 조합을 제외하면 학습 후보는 14·16조합이다. 이는 기존 선정 명세의 가능 조합이며 현재 학습 실적이 아니다. DC·송신원 검토와 native 60MS/s 로더가 필요하고 RFUAV와 혼합하거나 같은 학습 집합으로 합치지 않는다. [기존 독립 데이터셋 선정 명세](../../docs/DIVERSITY_MIXTURE_PLAN_KO.md).

## 다음 비교

우선 RFUAV 안에서의 원파형 시간 범위를 확대한다. 준비·유사도 검토를 통과하면 현재와 같은 U-Net 구조, 초기화, 원기록 분할, 검증 사례, 업데이트 예산으로 데이터 범위의 효과를 비교한다. 기종 반복 허용이나 손실·구조 변경까지 동시에 적용해 원인을 혼동하지 않는다. 전력·위상 증강은 원기록 다양성의 대체물로 세지 않는다.

현재 준비 worker는 CPU 코어 14/15, 낮은 CPU/I/O 우선순위, 작은 순차 읽기 버퍼를 사용한다. 초기 실행의 최대 RSS는 약 165MiB였고 기존 GPU는 정상 학습 중이었다. 데이터 준비는 완료 결과를 검토하기 전 자동으로 학습에 편입하지 않는다.
