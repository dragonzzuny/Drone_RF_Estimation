# 자료 선정·수신 조건·합성 규칙 갱신

2026-10-07. 사용자가 지적한 수신기 차이를 통제하기 위해 **단일 데이터셋·같은 대역**을 주 실험 조건으로 고정했다. 서로 다른 데이터셋의 파형을 합성하는 것뿐 아니라 합쳐서 학습하는 것도 제외했다. 주 실험은 RFUAV이며, DroneDetect는 자체 자료로만 수행하는 독립 보완 후보이다.

## 완료한 작업

| 항목 | 확인 결과 |
|---|---|
| 자료 선택 | RFUAV 5학습 기종, Autel 보류. DroneDetect 6학습 후보 코드, DIS/Parrot Disco 보류 |
| 데이터셋 간 조합 제거 | 최초 후보 중 학습 46조합, 미학습 조합 검사 2조합, 미학습 기종 검사 15조합 제외 |
| RFUAV 같은 대역 조합 | 단일 5개, 두 성분 4개, 세 성분 1개 |
| 실제 입력 목록 | 학습 120,000행, 검증 630행. 학습은 50 epoch분이며 독립 녹음 수가 아님 |
| 변인 통제 검사 | 7개 코드 검사 통과. 실제 모든 행의 데이터셋·대역·파일 역할 검사 및 결정적 재생 일치 |
| 수신기 메타데이터 | RFUAV 14묶음 모두 USRPX310, 100MS/s, IF bandwidth 100MHz. ScaleFactor는 60/85/90으로 다름 |
| CPU 병행 작업 | 새 목록의 검증 및 첫 두 학습 epoch 시간 문맥 특징 준비. 별도 소스 스냅샷, CPU 12/13, 낮은 우선순위 |
| GPU | 기존 RFUAV 5종 시간 문맥 대조 실행 중. 새 같은 대역 규약의 본 학습은 아직 시작하지 않음 |

수신기 모델이 같다는 메타데이터는 물리 수신기 개체·전체 설정·잡음 조건까지 같다는 증거는 아니다. 원문도 X310 기반 수집·재생 구성을 설명하지만 개별 파일의 하드웨어 동일성을 대신 확인해 주지는 않는다. [RFUAV 원문](https://arxiv.org/html/2503.09033v2#S4.SS1).

새 조건의 RFUAV 5.8GHz 세 성분 조합은 AVATA2+FPV COMBO+MAVIC3 PRO다. 2.4GHz는 현재 MINI3·MINI4 PRO뿐이므로 서로 다른 세 기종 조건을 만들지 않았다. 새 모델 대조의 검증 목록은 이전 대역 간 합성 목록과 달라, 기존 검증 수치와 직접 비교하지 않는다. 전체 규약은 [현재 계획](../../docs/DIVERSITY_MIXTURE_PLAN_KO.md)을 따른다.

## DroneDetect 입력 검사

새 자료를 학습에 합치기 전 수행한 CPU 검사는 CLEAN 학습 후보 51파일의 앞부분만 읽었다. 검증 17파일, 확인용 17파일, DIS 보류 파일의 I/Q는 이 작업에서 읽지 않았다. 복소 표본이 유한하고, 60→100MS/s 변환 및 1–3개 복소 덧셈 구성이 가능함을 확인했다. 정답 성분을 빼서 얻은 수치 오차는 합성 코드의 산술 검사이며 분리 모델의 성능이 아니다.

51구간의 DC 전력 비중은 최소 0.72%, 중앙값 38.60%, 최대 98.98%였고 43구간이 10%를 넘었다. DC의 출처를 수신기 오프셋으로 확정하지 않았고, 해당 자료를 제외하거나 DC 제거를 채택하지 않았다. 변동 성분·시간 구간을 추가 확인해야 한다.

처음 관찰된 최대 전력 차이 −1.452dB는 서로 다른 시간 범위의 평균을 비교한 값이었다. 해당 PHA_ON 학습 파일을 다시 확인하면 전체 재표본화 전후 차이는 −0.0020dB, 시간 범위를 맞춘 비교는 +0.0062dB다. 이를 필터가 1.45dB의 신호 전력을 소실시켰다는 근거로 해석하지 않는다. 이 재검사는 이미 읽은 학습 파일 한 개의 동일 앞부분만 사용했다.

사용자 최신 지시로 실제 DroneDetect 후속 실험은 원래 60MS/s를 유지한다. 이 검사에서 만든 100MS/s 캐시는 학습 자료로 승인하지 않는다. DroneDetect 반복 번호를 독립 날짜로 보거나 CLEAN을 기체 단독 송신 정답으로 간주하지 않는다. [수집 설명](https://www.mdpi.com/2226-4310/9/12/738).

## LoRa/Crossfire 수록 확인

로컬 연구 자료 46,181개 파일명, 백업 자료 목록 121,295항목, ZIP 4개 내부 목록과 SigMF 메타데이터 123개를 확인했다. LoRa/Crossfire/ELRS/CRSF 키워드로 확인된 I/Q 파일이나 메타데이터는 없었고 검색 오류도 없었다. 비공개 가족 자료 등 연구와 무관한 폴더는 검색하지 않았다. 이 결과는 이름 없는 기록 안에 그런 파형이 전혀 없다는 뜻이 아니다.

RFUAV의 TX16S 등 제품명이나 기존 문서의 ELRS 표기만으로 수집된 파형을 LoRa로 확정하지 않는다. [ExpressLRS 공식 모드 설명](https://www.expresslrs.org/quick-start/transmitters/lua-howto/)에도 LoRa와 FLRC 모드가 구분돼 있다. [OSU 공개 LoRa](https://research.engr.oregonstate.edu/hamdaoui/datasets)는 IoT 장치의 별도 실험 후보이며 드론/Crossfire 정답이 아니다. 이번 단일 데이터셋 드론 주 실험에 포함하지 않는다.

## 증거 파일과 해석

- [현재 선택 명세](within_dataset_selection.json): 데이터셋별 역할·조합, RFUAV 수신 설정, 제거한 조합 수.
- [새 입력 준비 규약](same_band_preparation.json), [전체 입력 목록 검사](within_dataset_execution_audit.json): 해시·행 수·원기록 분할과 검사 시점 작업 상태.
- [자료명·메타데이터 검색](signal_availability_audit.json): 검색 범위와 한계.
- [앞부분 I/Q 검사](diversity_selection_audit.json): 51개 학습 구간의 수치. 이 파일에 포함된 초기 통합 조합 목록은 폐기된 v1 후보이며 현재 학습 규약이 아니다.

새 선택 명세는 v1 통합 후보를 대체한다. v2에 남았던 전역 100MS/s 표기도 v3에서 데이터셋별 원래 표본률로 정리했다. 원자료·기존 학습·기존 보류 파일은 변경하지 않았다. 이번 보고는 선택 및 입력 검증 완료 보고이며 새 분리 성능 결과가 아니다.
