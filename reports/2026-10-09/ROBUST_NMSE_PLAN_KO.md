# U-Net의 손실 균형: 동일 시작 가중치의 후속 대조

## 질문과 근거

현재 선택 U-Net e4의 한 극단 TRAIN batch32를 재계산했을 때, 한 사례가 출력층의 개별 gradient norm 합의 79.16%를 차지했다. 같은 출력·원래 PIT 대응에서 정규화 오차에 `log1p`를 적용하면 29.13%였다. [수치 진단](UNET_HEAD_GRADIENT_E004.md). 이 결과는 선택한 batch와 출력층에 한정되며, 전체 학습 실패 원인이나 개선된 복원 성능을 입증하지 않는다.

검증할 가설은 **큰 상대 오차가 있는 일부 사례의 영향을 완만하게 하면, 같은 U-Net이 다른 사례까지 더 고르게 학습하고 검증 파형 오차를 줄일 수 있는가**다. 반대로 어려운 약신호를 덜 학습해 성능이 악화될 수도 있다. 실패 조건을 평가에서 제외하지 않는다.

음성 분리의 [von Neumann 등, SA-SDR, ICASSP 2022](https://arxiv.org/html/2110.15581v2)는 2.3절에서 log1p-MSE를 다루며, 3절에서는 신호별 손실을 집계하는 방식의 영향을 분석한다. 이번 후보는 해당 논문의 SA-SDR 구현이나 RF 검증 결과가 아니다. 정답 에너지로 정규화한 오차에 자연로그를 적용하고 기존 coherence·배경 항을 함께 사용하므로 식이 다르다.

## 바꾸는 항

기존 손실이 선택된 출력 슬롯마다 `u + coherence`를 평균한다면, 후보는 `ln(1+u) + coherence`를 평균한다. `u`는 기존 분모와 비활성 슬롯 규칙을 그대로 사용하는 정규화 제곱 오차다. 비활성 슬롯에도 같은 변환을 적용한다. 배경 손실과 개수 cross-entropy 계수 0.1은 유지한다.

PIT 대응은 각 모델의 예측에서 기존 NMSE+coherence 비용으로 결정한다. 후보의 로그 손실에 맞춰 순열을 새로 최소화하지 않는다. 원래 파형 대응 규칙을 고정하고 가중 효과를 분리하는 비교다. 미분 계수는 `1/(1+u)`이므로 큰 `u`의 영향은 완만해지지만, 그 표본을 제거하거나 손실을 0으로 자르지는 않는다. 시간·주파수 입력 변환이나 log-STFT 손실이 아니다.

## 고정 조건

| 항목 | 두 군의 공통 조건 |
|---|---|
| 모델 | 전체 32,142,859 파라미터 STFT U-Net, 구조 변경 없음 |
| 시작점 | 동일한 main 구조 비교의 선택 e4/300업데이트 가중치 |
| optimizer | 양쪽 모두 새 AdamW, lr 5e-4·weight decay 1e-4·clip 1 |
| 추가 예산 | 각 3 epoch, 225 optimizer 업데이트, 실효 batch 32·microbatch 1 |
| 자료 | 원 규약의 TRAIN 일정 1–3을 양쪽에 동일하게 재사용; 새로운 원기록이라고 주장하지 않음 |
| 평가 | 같은 개발검증 630개, 기존 raw I/Q NMSE·복소 SI-SDR·약신호·개수 지표 |
| 선택 | 초기 e0 포함 2/3성분 평균 raw NMSE 최솟값; 학습 손실값으로 서로 다른 군을 비교하지 않음 |
| 순서 | 홀수 epoch는 기존→후보, 짝수는 후보→기존 |
| 저장 | 실제 epoch·선택 checkpoint·optimizer/RNG·원자료 명세와 코드 해시 |

미세조정 epoch는 부모 모델의 epoch와 구분한다. 양쪽에 같은 optimizer 재시작을 적용하므로 기존 모델의 단순 연속 e5와도 같은 실험으로 부르지 않는다. 고정된 seed0의 초기 개발 비교이며, 기종 일반화나 충분한 수렴의 근거가 아니다.

## 평가와 실행 상태

채택에는 같은 추가 예산의 대조군보다 **2/3성분 모두 raw NMSE 감소와 SI-SDR 증가**가 필요하다. 약신호 NMSE·SI-SDR도 별도로 확인한다. 학습 gradient norm과 clipping 비율을 기록해, 출력층 사후 진단을 실제 전체 모델 학습 기록과 구분한다. 큰 전력차를 제외한 점수로 전체 점수를 대체하지 않는다.

새 코드의 복소 순열·공통 배율·완전 복원·극약신호 미분을 확인하고, 축소하지 않은 전체 U-Net·63,872 복소 표본으로 CPU 기울기를 검사한다. 실제 GPU 실행은 긴 복소문맥 비교와 예약된 출력 방식 TRAIN4 진단 뒤에 연결한다. 준비·대기 상태는 학습 중으로 표시하지 않는다. 실제 상태는 `local/robust_unet_comparison_20261009_v1/STATE.json`, 완료 epoch는 `ROBUST_UNET_PROGRESS`에 남긴다.

RFUAV 같은 대역·수신 중심 차이·native 100MS/s·원기록 분할을 유지한다. 조종기 단독과 명시적 결합 라벨을 편입하지 않는다. Autel과 예약된 확인용 파일은 열지 않는다.
