# 긴 I/Q 문맥 대조 실행과 상용 디텍터 시간의 해석

2026-10-08. 사용자의 계속 실행 및 긴 신호 관측 요청을 반영했다. 기존 진단에서 학습률·출력 배율만으로 세 성분 잔차가 충분히 줄지 않아, **같은 원파형 U-Net의 복소 관측 길이 대조**를 시작했다.

## 상용 디텍터는 얼마나 오래 관측하는가

공개 자료의 탐지 지연과 단일 I/Q 분석창 길이를 구분해야 한다.

| 공식 자료 | 확인한 시간 관련 내용 | 해석 범위 |
|---|---|---|
| DJI AeroScope stationary unit | 이상적인 조건에서 빠르면 2초에 기체 정보 획득 | 탐지·정보 획득 지연이며, 2초 길이 I/Q를 한 번에 신경망에 넣는다는 뜻이 아님 |
| DroneShield 2024-11 RF 센서 업데이트 | 스캔 17% 가속, 임무 설정으로 scan time 조절 가능 | 해당 자료에 절대 분석창 길이·dwell time 수치 없음 |

출처: [DJI 공식 제품 설명](https://www.dji.com/aeroscope), [DroneShield 공식 업데이트](https://www.droneshield.com/media/press-releases/4q24-firmware-updates-released). 2026-10-08 본문 확인. 두 자료만으로 모든 상용 제품이 같은 관측 길이를 쓴다고 일반화하지 않는다. 공급자 자료의 시간 표현을 독립 성능 검증으로 바꾸지도 않는다. 상용 탐지·정보 해독은 각 성분의 원시 I/Q 복원과 목표가 다르다.

R&S ARDRONIS 세미나 PDF는 검색 색인에 있었으나 본문 URL이 404여서 이번 수치 근거에서 제외했다. 따라서 검색 요약의 최소 hop 길이를 분석창 길이로 옮기지 않았다.

우리 관측 길이는 상용 제품의 비공개 구현을 추정해 정하지 않았다. [이전 RFUAV 학습 자료 분석](../2026-10-06/TEMPORAL_STRUCTURE_KO.md)에서 약 2.5/4/5ms 전력 반복 후보가 관찰됐다. 현재 0.63872ms 복소 입력은 이런 사건 여러 개를 함께 보기 어렵다. 10.48576ms를 첫 긴 관측 후보로 정했으며, 모든 반복·프로토콜에 충분한 길이라고 확정하지 않는다.

## 현재 실행

- 두 군 모두 같은 32,355,203파라미터 모델, 같은 초기 가중치·seed 0이며 기존 e22 가중치를 읽지 않는다.
- 긴 군은 원시 100MS/s I/Q 1,048,576표본(10.48576ms)을 본다.
- 짧은 군은 동일 배열에서 채점 구간 밖 복소 표본을 가려 0.63872ms만 본다. 두 군의 계산 모양과 파라미터가 같다.
- 기존 20.97152ms 전력 특징의 시간 평균은 두 군에 같은 보조 정보로 제공한다. 긴 군에는 추가로 시간 순서가 있는 복소 표본이 제공된다.
- 출력·손실·평가는 기존과 같은 63,872표본이다. 긴 군에 더 많은 정답 표본을 감독하는 차이를 만들지 않았다.
- 같은 학습 12,000혼합·5 epoch·각 1,500업데이트, effective batch 8. 같은 cosine LR 1e-4→1e-5를 쓴다.
- 2/3성분 평균 NMSE를 사전 선택 지표로 정하고, 두 성분 개수별 NMSE·SI-SDR·약신호 오차·개수 추정을 따로 보고한다. 1성분도 별도 보고한다.

앞서 준비하던 STFT 대 1D U-Net 학습은 실행 전에 우선순위를 바꿨다. 이번 결과는 동일 원파형 구조의 긴 문맥 대조이며, STFT 대비 구조 우월성의 matched comparison으로 부르지 않는다. [코드와 정확한 규약](../../experiments/rfuav_waveform_20261008/README.md).

표본을 16개씩 채널로 재배열해 계산 길이를 줄인다. 표본을 삭제하거나 복소 위상을 평균하지 않는다. 재배열·역재배열은 모든 표본과 복소 사인파에서 정확히 일치했다. 이후 학습된 압축·복원이 무손실이라는 주장은 아니다.

## 완료한 실행 전 검사

- 수치 검사 4개: 재배열 보존, 잘못된 길이 거부, 전체 초기 가중치·파라미터 일치, 학습률 예산.
- 실제 크기 GPU 검사: 양쪽 1/2/3성분의 순전파·역전파·optimizer 업데이트 통과. 검사 가중치는 폐기했다.
- GPU 최고 할당량: 짧은 군 888,714,240 bytes, 긴 군 880,325,632 bytes. 이는 작은 사전 검사에서의 관찰치이며 본 학습 최고치와 구분한다.
- 짧은 군은 창 밖 위상을 바꿔도 출력이 정확히 동일했고, 긴 군 출력에는 변화가 있었다. 이는 입력 경로 연결 검사이며 긴 문맥의 성능 이점이 아니다.
- 정답·개수 라벨을 바꿔도 추론 출력이 동일했다. 네 출력의 합 오차는 약 2e-15였다.
- CPU 병행 검사: 학습 18혼합에서 긴 입력의 채점 구간과 기존 혼합·정답 합의 바이트 일치를 확인했다. 검증·보류 I/Q는 이 CPU 검사에서 읽지 않았다.
- 전체 스케줄 좌표 검사에서 학습 12,000개 중 6,129개, 검증 630개 중 309개가 좌우 대칭 문맥을 갖는다. 나머지는 원 20.97ms 문맥 경계 때문에 좌우 길이가 달라지며 그대로 두 군에 사용한다.

기존 원기록 그룹 분할, 같은 데이터셋·같은 원 RF 대역, 중심 정렬 합성, 조종기 클래스 제외 조건을 유지한다. 검증 대역폭 조건 차이와 기록 잡음 포함 정답이라는 제한도 유지한다. Autel은 모델 선택에서 제외한다.

실제 작업 디렉터리는 `local/waveform_context_20261008_v1/`이며 PID·epoch·업데이트·검증 수치는 자동 기록한다. 아래 동봉 실행 기록은 저장 시점의 상태이며 실시간 상태는 해당 디렉터리에서 확인한다. 학습을 시작했다는 사실과 성능 개선은 구분한다.

[봉인된 규약·GPU/CPU 검사·실행 기록](LONG_IQ_CONTEXT_LAUNCH.json). 본 학습 PID 3286411의 실제 업데이트 진행을 확인했다. 별도 CPU 모니터는 `local/waveform_context_20261008_v1/monitor/STATUS_KO.md`를 30초마다 갱신하며, 양쪽의 공통 완료 epoch마다 비교 JSON을 저장한다. 이는 로컬 자동 보고이며 대화 메시지가 자동 발송된다는 뜻은 아니다.

첫 긴 문맥 군의 1 epoch/300업데이트와 검증을 완료했다. 두 성분 평균 NMSE는 29.599774, 세 성분은 1.681424로 아직 오차가 크다. 두 성분의 사례별 평균 NMSE 중앙값은 0.681369이며, 작은 정답 전력을 가진 일부 사례가 평균을 크게 높인다. 사전 평균 지표를 중앙값으로 교체하지 않는다. 이 시점에는 짧은 군의 동일 예산 검증이 끝나지 않아 긴 문맥의 이점을 판단하지 않았다. 처음부터 학습한 첫 epoch를 기존 e22 전이 모델과 공정한 구조 비교로 해석하지 않는다.
