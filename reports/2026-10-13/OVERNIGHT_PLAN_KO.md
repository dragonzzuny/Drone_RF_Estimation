# 2026-10-13 오전 8시까지 연구 실행 계획

사용자 지시: 현재 학습을 총100epoch까지 마친 뒤 네 단계의 후속 과정을 수행하고,
관찰 결과에 따라 실험·문헌조사·재검증을 계속한다. 기존 중지 실험 큐의 재개는 아니다.

1. **100epoch 완료·선택.** 고정 B DEV630의 기존 macro NMSE 규칙으로 최선 선택.
   마지막 epoch와 최선 epoch를 구분하고, 2/3성분 NMSE·복소SI-SDR·최약NMSE를 함께 보고한다.
   모델·optimizer·scheduler·RNG를 보존한 현재 실행을 변경하지 않는다.
2. **단계별 출력 배정 진단.** 이미 개발에 사용한 FPV+Mavic3Pro 2ms 사례를 고정한다.
   epoch79에서 0도 단일추론, C4, C8, 예측만 사용하는 창간 순서 대응,
   Hann/균일 병합을 비교한다. 정답 기반 구간별 복소 회귀는 분석에만 사용한다.
   혼합합 보정 전후도 기록하되 보정 전 공통 성분은 식별되지 않는 자유도여서
   이 비교만으로 균등 보정의 인과효과를 주장하지 않는다.
3. **최종 선택 모델의 복원·패킷 확인.** 같은 사례 재평가와 고정 B 진단 표본을 사용한다.
   목표 출력의 패킷 보존, 다른 출력의 정답 성분 누출, 전체/짧은 구간 복원오차를 같이 본다.
   CRC 성공만으로 분리 성공이나 식별 향상을 주장하지 않는다. 혼합 자체도 CRC가 성공한 사례다.
4. **관찰에 따른 한 가지 우선 개선.** 창 내부에서 배정이 바뀌면 연속 구간에 하나의
   대응 관계를 적용하는 학습을 우선한다. 창 연결이 주원인이면 추론의 예측 기반
   순서 추적부터 검사한다. 새 비교의 시작 체크포인트·학습 자료·업데이트 예산·평가 표본·
   중지 기준을 실행 전에 별도 등록한다. 전체 용량을 유지한다.

현재까지의 증거는 같은 녹음의 시간 분리 B와 반복 확인한 개발 사례다.
보류 기종/최종 확인 자료는 열지 않는다. 원기록 수와 혼합/창 수를 구분한다.
실패한 조건과 지표 간 절충을 보존하고, 근거 없는 범용성·완벽 복원·논문화 확정 표현을 쓰지 않는다.

CPU 진단은 GPU100epoch와 병행하되 CPU2코어·낮은 우선순위·메모리 제한을 사용한다.
새 GPU 작업은 기존 실행 완료 후 같은 GPU lock으로 직렬화한다.
epoch마다 실제 검증 완료와 감사 통과를 확인해 대화로 보고한다.
오전8시에는 완료/진행/보류, 최선 수치, 원인에 관한 새 관찰, 다음 판단을 정리한다.

방법 근거: [uPIT](https://arxiv.org/abs/1703.06284),
[혼합 일치와 가중 보정](https://arxiv.org/abs/1811.08521).
이는 음성 분야의 방법 근거이며 현재 RF 자료에서의 효과를 뜻하지 않는다.
