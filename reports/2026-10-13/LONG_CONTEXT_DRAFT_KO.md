# 실제 파형 입력 확대 — 조건부 후속 후보

현재 상태: **준비 중, 학습 등록·실행·예약 없음**. 기존100epoch와 공통 순열 비교를 바꾸지 않는다.

앞선 비교는 세 개의0.63872ms 예측에 공통 순열을 적용한다. 한 번의 forward는 여전히
짧은 창만 본다. 이 비교와 최종 부모의 고정2ms 입력 진단 뒤에도 구간별 출력 배정 문제가
남으면, 같은 세 창을 실제로 이어1.91616ms 전체를 한 번에 처리하는 비교를 검토한다.

동일 초기 부모·혼합 일정·자료·파라미터32,142,859개·공통 순열·창별 손실 정규화와
업데이트 수를 유지하고 입력 묶음만 변경하는 것이 우선 후보다. 대조군은 앞서 한 번
학습한 shared 궤적을 재사용한다. 신규 실행의 예산·평가·중지 규칙과 초기 SHA는
결과를 확인해 채택할 때 별도 계획으로 봉인한다.

입력 확대는 합성곱이 창 경계를 통과하게 하고 GroupNorm/입력 크기 정규화의 범위도
바꾼다. 따라서 '수용영역만 변경했다'는 순수 요인 주장이나 장기 기억을 이미 도입했다는
주장은 하지 않는다. 추가 메모리 모듈·LSTM/Transformer는 아직 구현하지 않았다.

GPU 메모리에는 전체 모델을 유지하고 U-Net 블록을 역전파 때 다시 계산하는
activation checkpointing을 준비한다. 저장점 이름/텐서·forward·기울기 동일성을
CPU 합성 텐서로 검사하고, 실제 길이의 GPU 학습 사전 점검은 기존 작업 종료 후
별도로 해야 한다. 체크포인팅은 계산과 메모리의 교환이며 성능 개선 방법 자체가 아니다.
[설치 버전PyTorch2.8 공식 문서](https://docs.pytorch.org/docs/2.8/checkpoint.html).

구간 사이 정보를 전달할 필요가 확인되면
[SkiM](https://arxiv.org/abs/2201.10800)의 구간 내부 처리와 구간 상태 전달을 참고할 수 있다.
이는 음성 분야 근거이며, 현 RFUAV 문제에 효과가 입증됐다는 뜻은 아니다.
