2026-10-11 사용자의 “다 진행해” 지시에 따라 대기열을 실제 변경했다. 기존 SepTDA GPU worker를 유지하고, 대기 중인 실행기만 교체했다. 현재 사용 중인 `five_candidates_20261010_v2`의 자료·검증·학습 코드·체크포인트·optimizer/RNG는 그대로 이어간다.

시간 순서 보존을 먼저 보는 이유는 현재 긴 문맥(20.8896ms)의 특징이 시간 평균 후 전달되기 때문이다. SepTDA의 추가 시간 경로는 짧은0.63872ms 창을 처리한다. 기존 ordered-context 후보는 긴 특징의 시간 변화를 학습 게이트로 다시 전달한다. 전체 긴 구간의 복소 I/Q를 순서대로 처리하는 구조와는 다르며, 긴 호핑 주기까지 충분히 관찰한다는 보장은 없다. 시간 정보 전달을 바꾸었을 때 복원 성능이 개선되는지를 확인하는 후보다.

고정 TRAIN6의 적합도 개선과 DEV630의 악화가 함께 관찰됐다. 이후 본체 고정 후보로 기존 복원 표현을 유지하며 추가 경로만 학습하는 가능성을 확인한다. 소수 학습 사례 진단은 원인 확정이 아니고, 두 후보의 입력·파라미터·학습 범위도 달라 순서 변경 자체를 정교한 단일변인 실험으로 표현하지 않는다.

실행 검사는 기존91개 소스·40개 고정 항목과4개 모델 사전 검사 파일을 검산했다. 대기 중인 기존 실행기 PID935459의 명령·자식 프로세스 없음·Sep 완료 전 상태를 확인한 뒤 해당 프로세스만 교체했다. 새 실행기 PID1817233은 `WAITING_SEPTDA_50`, 다음 후보 `ordered_context` 상태이며 Sep GPU PID930800과 알림 PID1022362는 유지됐다. 순서·이름 대응·원래 학습기 경로·진행 파일의 변경 이력 기록 모의 인계 테스트를 포함해4개도 통과했다.

원래 PROTOCOL SHA-256은 `911db1842f6dfe61dbd62666ad04d9ef35002a1312a0ffa8c803b06e9c12841e`로 유지됐다. 별도 실행 변경 명세 SHA-256은 `8f67ac665023734e938936270143c147bde871d01f47b4169cd8bfe053056490`이다. 실행 변경기는 원래의 독점 대기열 잠금·GPU worker·완료 영수증 검사를 재사용한다. 현재 순서는 진행 JSON/문서에도 별도로 표시한다.

CPU에서는 외장하드 원녹음 감사도 완료했다. 37범주·358파일·53XML묶음이 기존 목록과 일치했다. 현재 학습8묶음·83파일은 모두 사용 중이며 새 학습 묶음은0개 승인했다. 검증 VTSBW=20은 다섯 제품 모두의 학습에 없는 조건이다. 이 조건 차이와 원기록 다양성 제약을 보고하되 현재 분할을 바꾸지 않는다. Autel 및 기존 확인 자료를 학습에 넣지 않으며, 송신 방향 미확인 범주의 영상 표기를 기체 전용 정답으로 대신하지 않는다.
