# 긴 시간 문맥과 최대 세 신호 분리 구현

2026-10-06 사용자 지시에 따라 우선 범위를 **1·2·3개 신호**로 정했다. 최대 네 신호 지원은 이전 코드의 호환용으로 남기며 이번 실행 대상에 포함하지 않는다. 이번에 완료한 것은 모델·입력 구성과 CPU 검산이다. 새 모델의 GPU 학습, 복원 성능 및 개수 추정 정확도는 아직 측정하지 않았다.

## Transformer나 LSTM이 필요한가

필수는 아니다. U-Net의 합성곱도 관측 창 안의 시간 구조를 학습한다. 이번 후보의 핵심은 기존 0.63872ms 복원 입력에 **20.97152ms의 실제 혼합 문맥**을 더 제공하는 것이다. 짧은 입력 내부의 네트워크만 바꿔서는 입력 밖의 반복을 관찰할 수 없다. RF Challenge의 U-Net 커널 길이·WaveNet dilated convolution 연구도 RF 시간 구조를 활용할 근거이지만, 우리 기종에서의 개선을 보장하지 않는다. [RF Challenge III.B](https://arxiv.org/html/2409.08839v3).

| 문맥 경로 | 이번 구현 | 검증할 역할 | 전체 파라미터 |
|---|---|---|---:|
| 문맥 없는 U-Net | 기존 전체 본체, 세 신호+배경 출력 | 파형 기준선 | 31,391,752 |
| U-Net + TCN | 128채널, dilation 1/2/4/8/16/32, 단계별 3탭 합성곱 2개 | 버스트·반복과 시간에 따른 주파수 점유 변화 | 32,142,859 |
| U-Net + Transformer | 128차원, 4 head, 2층, 시간 위치 부호화 | 멀리 떨어진 시간 구간 사이의 관계 | 31,944,971 |
| U-Net + 양방향 LSTM | 2층, 방향당 64차원 | 앞뒤 문맥을 이용하는 순차 변화 | 31,747,083 |

모두 복원 본체의 64/128/256/512/1024 채널을 유지한다. 추가 모듈 때문에 전체 파라미터와 계산량은 같지 않다. 동일 데이터·업데이트 예산과 동일 본체 초기화로 비교하고 계산 비용도 별도 기록한다. Transformer/LSTM의 일반 동작은 [PyTorch TransformerEncoderLayer](https://docs.pytorch.org/docs/stable/generated/torch.nn.TransformerEncoderLayer.html), [LSTM](https://docs.pytorch.org/docs/stable/generated/torch.nn.LSTM.html)을 따른다. 특정 RF 논문 모델의 재현이라고 부르지 않는다.

## 입력과 연결

긴 문맥은 100MHz 복소 I/Q 2,097,152표본이다. 원신호별 긴 구간 전력으로 합성 배율을 정한 뒤 **복소수로 합쳐서** 문맥 특징을 계산한다. 개별 정답의 스펙트럼·주기·기종·신호 개수는 모델 입력으로 전달하지 않는다. 이 전력 처리 방식은 RFUAV 입력 후보이며, 이전 DRFF 전력 보존 대조에서 성능이 악화한 사실은 그대로 유지한다.

1024표본 주기 Hann FFT를 64개 주파수 대역으로 묶고, 혼합의 상대 대역 점유와 상대 전력 포락선으로 65채널을 만든다. 연속 8프레임을 묶으면 256개 시간 토큰, 간격 81.92μs가 된다. 이 경로는 거친 전력 구조를 읽으며 개별 홉이나 위상을 복원하는 경로가 아니다. 로그 변환은 문맥 입력 특징의 범위 조절이며, 기존에 시험한 log-STFT 손실을 추가한 것이 아니다.

정밀 복원 경로는 같은 혼합에서 잘라낸 63,872표본의 복소 STFT다. FFT 512, hop 128, `center=True` 조건을 사용한다. 긴 경로의 출력을 U-Net의 bottleneck 시간 위치에 맞춰 보간해 더한다. 네 번의 2배 pooling을 거친 t번째 지점의 중심은 짧은 창 시작에 `(16t+7.5)×128`표본을 더한 위치다. 길이를 단순히 맞춰 늘리는 방법과 구분했다. 문맥 가장자리는 끝 토큰을 복제한다.

문맥 TCN의 합성곱 수용 범위는 최대 253토큰(약 20.73ms)이며 경계에서는 실제 이웃이 줄어든다. Transformer와 양방향 LSTM도 이 약 21ms 범위 안의 문맥을 사용한다. 미래 표본을 포함하는 오프라인 설계다. 실시간 지연을 달성했다고 주장하지 않는다.

## 세 신호와 개수 정답

최종 파형은 순서가 정해지지 않은 세 출력과 별도 배경 출력이다. 세 슬롯의 6가지 순열 가운데 **전체 평가 파형에 하나의 순열**을 적용하는 PIT를 지원한다. 한두 신호를 합성할 때 남는 정답 슬롯은 0이다. 현재 합성의 수신 잡음은 각 원기록 정답에 포함되므로, 배경 0 정답이 잡음 없는 자료라는 뜻은 아니다.

긴 문맥을 읽은 별도 분류기는 1·2·3개 logit을 출력한다. 이 분류 결과로 파형을 즉시 삭제하거나 특정 기종에 배정하지 않는다. 먼저 개수 정확 일치율·MAE·혼동행렬과, 순열을 맞춘 성분별 NMSE·SI-SDR을 별도로 평가한다. 세 출력 중 실제 유효 출력을 선택하는 규칙과 긴 추론의 창 간 추적도 검증 전에 고정해야 한다. 현재 짧은 창 구조 검사는 그 추적 기능의 구현을 뜻하지 않는다.

`construction_count`는 합성에 넣은 기록 수다. 거의 잡음뿐인 기록·짧은 비송신 창이 있을 수 있어 이것만으로 실제 물리 드론 대수 정답을 만들지 않는다. 이번 CPU 사례의 `count_eligible`은 모두 False로 보존했다. 활동·수집 근거를 확인한 개수 정답만 별도 개수 손실에 사용한다. 이 마스크는 자료 해석을 명시하는 코드 장치이며 사용자에게 별도 승인을 요구하는 절차가 아니다. 0개 입력의 개수 분류와 4개 이상 입력은 이번 1–3개 분류기의 검증 범위에 포함되지 않는다.

## 실제 수행한 검산

학습 후보의 5개 기종에서 각 1개, 모든 서로 다른 2기종 조합, 모든 서로 다른 3기종 조합을 생성했다. 학습 캐시 154개의 해시를 확인했고 검증·보류 파형은 읽지 않았다.

| 합성에 넣은 기록 수 | 생성 조건 수 | 전력 조건 |
|---|---:|---|
| 1 | 5 | 단일 기록 |
| 2 | 30 | 두 성분 전력차 −10/0/+10dB |
| 3 | 70 | 동일 전력, 각 성분을 번갈아 10dB 약하게 또는 강하게 설정 |

105조건 모두 짧은 혼합과 세 정답의 합이 정확히 일치했다. 문맥 특징은 모두 65×256 형태의 유한 값이었다. 세 문맥 인코더는 실제 혼합 특징을 받아 128×256의 유한 값을 출력했다. 모델은 무작위 초기화 상태이며 이것은 복원·개수 정확도가 아니다. 서로 다른 RF 중심 주파수의 기록을 겹친 사례는 주파수 기준을 바꾼 합성 기저대역이다. 동일 기종 여러 실제 기체 및 실제 세 대 동시 수신을 검증한 결과가 아니다.

CPU 14·15번, nice +10, 낮은 I/O 우선순위로 실행했고 23.89초, 최대 RSS 약 750MiB를 사용했다. 같은 시점의 기존 GPU 실험은 별도로 유지했다. [해시·실행 결과](context_three_inputs.json)에 상세 범위를 보존했다.

전체 단위 검사 34개가 통과했다. 추가 7개는 1/2/3개 합성 재연산, 상쇄 간섭의 복소 합, 문맥 시간 정렬, 세 슬롯 PIT, 개수 정답 제외 마스크, 세 전체 모델의 출력 합·역전파·문맥 반응, 기존 가중치 호환과 시간 평균 대조를 검사했다. CPU 모델 검사는 공간 크기를 줄인 입력으로 구조를 확인한 것이며 본체 채널 수를 줄인 모델 학습이 아니다. 정규 512×500 입력의 GPU 학습 메모리·처리량 검사는 아직 남아 있다.

## 다음 비교 순서

우선 TCN에서 시간 순서를 유지한 문맥과 시간 평균만 남긴 문맥을 **각각 학습**해 비교한다. 두 조건의 파라미터 수·본체 초기화·자료·업데이트 예산은 같다. 시간 평균 대조는 시간 변화와 위치별 정보 모두를 없애므로 결과를 주기성 하나의 효과라고 해석하지 않는다. 추론 시에만 문맥을 바꾸는 검사는 분포 변화가 섞이므로 주 비교를 대신하지 않는다.

이후 Transformer·LSTM으로 교체해 동일한 데이터와 업데이트 예산에서 비교한다. 기존 두 신호 고정 모델과 세 출력 모델의 단순 차이는 시간 모듈 하나의 효과가 아니다. 1/2/3개와 각 약신호 위치를 나누고, 개수 추정 오류와 복원 오류를 함께 보고한다. 최종 모델·활동 정답·학습 목록·선택 규약을 봉인하고 전체 입력 GPU 사전 검사를 통과한 뒤 새 자료 학습을 시작한다. **현재 새 모델 학습 및 GPU 큐 등록은 완료되지 않았다.**
