# 시간 문맥 대조의 실제 실행 연결

2026-10-06 23:59 KST 확인. 최대 세 신호 목표를 학습·검증 실행기로 연결하고 **새 GPU 대조를 실제 대기열에 등록**했다. 현재 GPU에서는 기존 비로그 STFT 크기 손실 N이 43/50 epoch를 진행 중이다. 새 시간 문맥 모델의 학습·성능 결과는 아직 없다.

## 완료한 준비

- 전체 U-Net+TCN의 두 군을 같은 초기화·32,142,859 파라미터·혼합 목록·손실·학습량으로 비교한다. 한 군은 시간 문맥을 유지하고, 다른 군은 같은 경로에 시간 평균 문맥을 제공한다.
- 1·2·3개 합성 기록 성분을 각각 epoch당 800개로 배정했다. 군별 50 epoch, 120,000예제, 3,750업데이트다. 검증은 원기록 묶음이 다른 고정 630조건이다.
- CPU에서 검증 630개와 첫 두 학습 epoch 4,800개의 문맥 특징을 완성했다. 다음 특징은 두 군의 진행보다 최대 2개 epoch 앞서 준비한다. 표본 재검산에서는 저장 특징·짧은 정답·혼합이 긴 원 I/Q 합성의 재계산과 정확히 일치했다.
- 43개 CPU 검사가 통과했다. 복소 STFT 왕복, 파형 손실의 전체 모델 역전파, 세 신호 PIT, 시간 정렬, 불명확한 개수 정답의 구분, 프로세스 인수의 성공·경쟁·PID 재사용 처리를 포함한다. 과정 중 끝 경계의 centered STFT를 허용하도록 좌표 검사를 바로잡았다.
- 0/상수 출력의 SI-SDR을 정상 0dB로 처리하지 않도록 했다. 평가 NMSE와 SI-SDR은 복소 배정밀도로 계산하며 정의되지 않은 값은 상태로 남긴다.

## 시작 전 확인과 본 학습

전체 길이 63,872표본으로 두 군의 GPU 순전파·역전파·메모리를 먼저 검사한다. 이후 첫 1/2/3개 학습 사례에 전체 모델을 48업데이트 적합해 파형 손실 감소를 확인한다. 이 진단의 가중치는 버린다. 본 대조는 두 군 모두 원래 seed 0 초기화에서 시작한다. 실패 시 작은 모델이나 CPU 학습으로 자동 변경하지 않는다.

본 학습은 매 epoch 검증하고, 5/10/25/50 epoch에 선택 체크포인트와 결과를 따로 보존한다. 저장 예시는 성능으로 고르지 않고 각 개수의 첫 검증 사례로 미리 정했다. 선택 기준은 개수별 평균 NMSE의 평균이며, 약한 성분과 개수 정확도도 함께 기록한다.

이 단계의 개수 정답은 **더한 기록 성분 수**다. 물리 드론 대수 eligibility는 False로 유지하고 실제 활동·송신원 확인과 분리했다. 새로운 개발 비교의 자료 해석 한계와 전력 처리 방식은 [실행 규약](../../docs/CONTEXT_EXPERIMENT_KO.md)에 고정했다. Autel 및 기존 DRFF 확인용 파일은 읽지 않았다.

## 실행 인수 확인

기존 감시 제어기를 인수했고 학습 worker의 PID·시작 시각·명령은 전후 동일했다. 학습 worker에는 신호를 보내거나 재시작하지 않았다. 기존 동결 의존성과 native 재개 체크포인트 해시를 재검사했다.

실행 순서는 다음과 같다.

1. 진행 중인 N 크기 손실 50 epoch 및 저장 출력 검산.
2. 기존 창 병합 270조건 및 검산.
3. 새 시간 문맥 모델의 GPU 검사·고정 혼합 진단·두 군의 50 epoch 대조.
4. 보존된 native RF Transformer 비교 재개.

새 비교는 준비만 된 계획이 아니라 살아 있는 제어기에 등록된 작업이다. 현재 단계는 **대기**이며 새 모델을 학습 중이라고 표시하지 않는다. 기존 detector와 DR-NMF D2 중단 상태를 유지한다.

[준비 수치·입력 해시·실행 인수 확인](context_execution_preparation.json), [확인 시점의 실행 상태](execution_snapshot.json). 이 문서와 JSON은 시점 기록이며 실시간 모니터가 아니다. 로컬 실행 상태는 `local/context_experiment_20261006_v1/queue/STATE.json`, 학습 상태는 그 실행 폴더의 `run/PROGRESS.json`에 기록한다.
