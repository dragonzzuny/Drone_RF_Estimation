# 동일10MHz 시간 분리 U-Net: 총100epoch 연장

2026-10-12 사용자의 명시적 지시로 기존50epoch를 **총100epoch**로 연장한다.
추가100epoch가 아니라51–100의50epoch,3,750업데이트를 더 수행한다.
총7,500업데이트·240,000합성 혼합 제시다. 동일 원녹음을 재사용하므로
240,000개의 독립 녹음을 뜻하지 않는다. 성능에 따른 조기 종료는 적용하지 않는다.

## 연속성

기존 `bandwidth_timeblock_20261011_v1`은 봉인된 코드와 계획대로50까지 수행한다.
새 `timeblock_extend100_20261012_v1` worker가 기존50epoch의 검증·CPU 감사와
worker 종료를 확인하고51epoch를 자동 시작한다. 사용자의 추가 개입을 요구하지 않는다.

- 출발점은 **마지막50epoch LAST**이며, 검증상 최선 epoch로 되돌아가지 않는다.
- 모델·AdamW 모멘트/업데이트 수·학습률 스케줄러·CPU/CUDA RNG를 그대로 복원한다.
- 기존 BEST는 별도로 이어받아1–100epoch 전체에서 같은 기준으로 선택한다.
- 전환 시50epoch·누적3,750업데이트·저장점/검증 해시·정확한 상태 복원을 검사한다.
- 원래1–50epoch의 코드·규약·결과를 수정하거나 과거부터100epoch였다고 바꾸지 않는다.

## 유지 조건

전체32,142,859파라미터의 `unet_mean`, 평균 장기 문맥TCN, 최대3개 성분과
잔여 출력, 원래 PIT NMSE+coherence/비활성·잔여 손실과0.1개수CE를 유지한다.
실수·허수STFT 입력과 I/Q 출력,FP32,유효batch32,epoch당2,400혼합/75업데이트,
무작위 성분 위상,8위상 예측 평균과 고정630개DEV 모두 유지한다.
추가8위상 일관성 손실·다른 구조·새 기종·새 대역폭을 동시에 도입하지 않는다.

51–100epoch의 혼합 일정은 기존 함수와 동일한 seed 규칙에 절대epoch번호를
넣어 미리 생성·고정한다. 매epoch1/2/3개 성분이 각각800개다.
동일 RFUAV·동일원RF대역 내 합성, 실제 중심주파수 간격,긴 구간 전력 정규화,
학습/검증 시간 구간과1초 이상의 raw-support 간격을 유지한다.
기존의2,020cache 감사와 고정DEV 특징을 재사용하며 검증 배열 바이트를 대조한다.
Autel·예약 확인자료·기존DEV20은 읽지 않는다.

학습률은50epoch의 값을 이어받는다. ReduceLROnPlateau(mode=min,factor0.5,
patience5,min_lr1e-6) 상태를 초기화하지 않는다. 학습률 감소는 총100epoch를
단축하지 않는다. 명시적 사용자 중지 또는 수치·무결성·자원 오류만 중지 사유다.

## 선택·보고·자원

선택 기준은 두/세 성분의 C8 macro 평균NMSE 최솟값이다. SI-SDR과 최약NMSE의
악화도 함께 보고하며 단일 지표 선택을 전체 지표 우월성으로 표현하지 않는다.
매epoch630개 검증,CPU 집계/저장점/optimizer검사,파일 보고와 로컬 바탕화면
알림을 유지한다. 자동 바탕화면 알림은 자동 채팅 전송이 아니다.

GPU는 한 trainer만 사용하고,CPU 특징은 낮은 우선순위와 제한된 코어로 병행한다.
완료epoch의 재생성 가능한 특징만 해시·사유를 남겨 정리한다.
모든epoch의 모델 저장점·최선·마지막/복구점·검증 결과는 보존한다.
추가 모델 저장점 약6.5GB와 작업 공간을 확인하고,epoch 시작 시1.5GB 여유를 요구한다.

현재 조건은 **같은 원녹음의 시간 분리 B 진단**이다. 학습 연장으로 독립 녹음
검증이 되지는 않는다. 기존 C 결과/최선 선택은 그대로 보존한다.
100epoch 이후200epoch나 새로운 구조를 자동 실행하지 않는다.
